## Findings that change the implementation plan

| ID | Evidence | Consequence and required decision |
|---|---|---|
| F01 | `EventBus.publish` calls subscribers inside an `RLock`; `StateStore.handle` writes JSON synchronously | Slow storage/output blocks every publisher. Preserve one reducer owner but isolate I/O and bound queues. |
| F02 | `controller.py` requires `--renderer-pid`; `run-system.sh` uses `wait -n` followed by cleanup of both children | Losing the avatar stops observation. Give daemon and presentation independent lifecycles and actual readiness handshakes. |
| F03 | `EventV2` is a frozen dataclass containing a mutable dictionary; `create()` copies only its outer mapping | Event contents can change after validation/audit. Canonical validated payloads must be recursively immutable, with defensive serialization. |
| F04 | `EventV2.__post_init__` accepts `True`/`1.5` as sequence, `True` as TTL and arbitrary privacy strings | Python annotations do not validate runtime data. Validate closed enums, integer types excluding booleans, finite bounded JSON and timestamps at the boundary. |
| F05 | `V1CompatibilityMapper` checks allowed field names but accepts `cpu_ratio="busy"`; current tests do not reject it | Payload validation is explicitly deferred in #4, so it is a partial foundation. Complete required fields, types, units and limits before wiring it into runtime. |
| F06 | `controller.run_adapter` emits configured-name `adapter.failed`; mapper has only selected MPRIS health identities | A sensor crash can itself fail migration ingress. Use authenticated component-instance identity and explicit health payload/state mapping. |
| F07 | `system.py` carries thermal state in replaceable telemetry; no dedicated thermal transition; missing temperature becomes `thermal_alert=False` | Coalescing can hide a warning, and sensor loss can look like recovery. Preserve threshold transitions separately and represent missing evidence as unknown. |
| F08 | `PrivacyClass` has `local` but no `sensitive`; capability/context examples require `sensitive` | Adopt one vocabulary across event, field, context, capability and egress schemas. See the runtime contract. |
| F09 | v0.13 promises replay while raw telemetry is ephemeral; DB/full-queue failure and clock restart semantics were unspecified | Define transactional checkpoints, sequence gaps, outbox delivery, replay limits and degraded operation before implementing storage. |
| F10 | `test_custom_sprite_config_is_ordered_without_spurious_warnings` expects v0.11; config points at v0.12 | Existing suite is not all green. Fix the stale expectation and verify the actual atlas contract in the next code PR. |
| F11 | `media_signals.py` exposes three profiles; the current design postpones interactive UI to A6 | Add a read-only panel and desktop behavior during A2, then an interactive renderer behind the same API. Do not encode menus or approvals as signals. |

F03/F04/F05/F06 were reproduced with isolated in-memory objects. No system
action was invoked. In particular, changing `event.data["cpu_ratio"]` to `99`
succeeds today. The production controller still uses v1, so these are blockers
for Core v2 integration, not evidence that v2 is already controlling the host.

Other code-review observations belong in the telemetry slice: keep hwmon sensor
identity instead of comparing the hottest arbitrary sensor to one universal
threshold; missing `MemAvailable` is unknown rather than 100% used; exclude
already-accounted guest CPU fields when computing `/proc/stat` totals.

The v0.13 modular-monolith decision stands. The next implementation PR should
close the contract and baseline-test gaps above. SQLite is the following slice,
not a reason to postpone strict ingress or a user-visible interface indefinitely.

## What the user will experience first

- Click/open Wisp's panel to see system status, fresh evidence and active issues.
- A sustained resource condition produces one understandable message and a
  recovery update; sensor loss explicitly says the reading is unavailable.
- Fullscreen/focus and locked sessions receive predictable presentation behavior.
- A local explanation can be requested later from exactly the evidence shown.
- User preferences and all source changes remain versioned/configurable; the
  host's telemetry, credentials and conversations never belong in Git.

There is no installed new application implied by this document. Each milestone
has its own target-host gate and rollback in the roadmap and desktop design.
